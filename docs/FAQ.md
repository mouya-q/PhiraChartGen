# 常见问题

**生成的谱面一定能在 Phira 里正常游玩吗?**
不能保证. 结构已通过校验, 但还没有系统的实机验证, 见 VALIDATION.md. 如果遇到问题, 请带上格式, 难度, Phira 版本提交 issue

**导入后音乐和音符对不上怎么办?**
在设置里调整 **谱面延迟** 后重新导出. MP3 的解码延迟因设备而异, 这是最常见的原因

**为什么提示没有检测到足够的节奏?**
音频可能过于安静, 全是环境音, 或节奏很不明显. 换一段节奏清晰的音频试试

**变速的曲子可以吗?**
目前只估计单一 BPM. 变速曲目的音符时间仍然准确, 但节拍网格不会跟随变速, 建议把 **网格吸附** 调小或关闭

**为什么 EZ 难度的长按很少?**
长按只来自持续存在的新音, 并且 EZ 会让出长按期间的其他音符

**支持哪些音频格式?**
取决于系统解码器, 一般支持 MP3, AAC, M4A, FLAC, OGG, WAV. 时长上限 15 分钟

**音频会被上传吗?**
不会. 即使启用 AI 增强, 上传的也只是曲速与按乐句统计的能量和起音数量, 见 AI_DATA_USE.md

**AI 增强不生效 / 测试连接失败?**
先在设置里点 **测试连接**, 界面会显示具体原因:
- 无法解析域名: 接口地址写错, 或当前网络无法访问该服务
- 密钥无效 (401) / 无权限 (403): 密钥错误, 或该服务限制了地区与来源
- 接口不存在 (404): 地址或模型名称不对, 多数服务需要带 `/v1`
- 请求过于频繁或额度不足 (429): 检查账户额度
- 返回了空内容: 可能选了推理模型, 换成普通对话模型
应用会自动处理 `max_completion_tokens`, temperature 不被支持, 缺少 /v1 与误粘贴完整地址这几种情况

**接口地址怎么填?**
填到版本号这一级, 例如 `https://api.openai.com/v1`, 应用会自动拼接 `/chat/completions`

**为什么毛玻璃效果不明显?**
Android 12 以下系统不支持 Compose 的模糊, 只会压暗封面. 也可以在设置中关闭

**导出的文件在哪里?**
在你选择的保存位置. **全部导出到文件夹** 会在所选文件夹中为每个难度创建一个 zip

**应用被系统杀死了, 进度还在吗?**
分析结果已缓存, 首页点击 **继续上次的曲目**. 需要原音频仍可访问

**如何反馈问题?**
设置页 **导出诊断日志**, 日志不含文件名与密钥, 附在 issue 中即可

**提示 "返回内容无法解析" 怎么办?**
说明服务连上了, 但模型的回复里找不到可用的 JSON. 提示后面会显示模型回复的开头. 常见原因: 选了不擅长遵循格式的模型, 或推理模型把内容放在了思考部分. 应用已兼容代码块, 前后说明文字与思考标签, 并优先请求 JSON 模式. 仍然失败时建议换成普通对话模型, 生成会自动使用离线结果

**为什么音符以前大多在右边?**
旧版本把频谱亮度直接映射到轨道, 而真实音乐的亮度普遍偏高, 导致约 77% 的音符落在右侧. 现在改用由玩家谱训练的小模型选择轨道, 并带左右平衡校正, 在 10 首真实歌曲上左/中/右约为 40/20/40, 与真人谱一致

**原生分析引擎是什么?**
用 Rust 实现的同一套分析算法, 通过 JNI 调用, 没有也不影响使用, 见 native/pcg-dsp/README.md
